# POPPŌ MEMBER PORTAL 1.0

## 確定仕様
- メールアドレスとパスワードで認証。運営がアカウントを発行。
- プロフィール変更は承認制、配信予定は即時反映。
- 既存公式サイトと同一リポジトリ。既存運営OAuth Workerは変更しない。

## 基盤設計
新規Cloudflare Workerと専用D1を使用する。マイグレーションは migrations/0001_initial.sql。
公開GitHubにはスキーマとコードのみを置き、実際のメールアドレス、パスワードハッシュ、申請、セッションを置かない。
member_id は既存 talents.json の id に対応する。運営による紐付けをサーバー側で検証する。
初回パスワード設定には短時間有効な一回限りの招待トークンを使用する。パスワードは個別salt付きの十分な強度のKDFでハッシュ化し、平文保存しない。
セッションはランダムなトークンのハッシュのみ保存し、期限・アカウント状態・権限を毎回確認する。ログイン試行制限、CSRF対策、失効、パスワード再設定を実装してから公開する。
ポータルの認証済み画面とAPIは同一Workerオリジンで提供する方針。GitHub Pagesには公開情報のみを置く。
プロフィール申請は許可フィールドだけを受理し、承認時に最新公開データとの差分を検証する。
配信予定の変更は本人のレコードだけをサーバーで検証し、公開JSONへの競合安全な更新を行う。GitHub認証情報はWorkerのSecretに保管し、メンバーには渡さない。
公開処理の成功を確認するまで反映済みと表示しない。GitHub Pagesのデプロイ遅延はあり得る。

設計・初期DBスキーマのみ。Worker API、認証UI、公開処理、D1作成・マイグレーション適用、動作試験は未実施。
実運用データを登録しないこと。
